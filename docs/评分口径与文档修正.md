# 首版调度规则与文档修正

本文件定义0.1版演示的可复现规则。原Word文档保持原样，未覆盖修改。若修改方案或代码，应同步此文件。

## 原文需要统一的地方

同温区甲、乙、丙、丁、己的贡献积分合计为24500，原文写23000。原文分项得分更接近按最高贡献归一化，而文字描述按总积分占比。按原文分项及0.4/0.3/0.2/0.1权重，甲64、乙61、丙50.3、丁27.7、己42，与原文综合分数不一致。

0.1版明确采用最高贡献归一化，等待分按实际模拟提交时刻计算，因此最终案例分数也与原文分项表有所不同，不能把它称为完全复现原文数值。

## 本版明确采用的规则

- 对同批次、温区相同、时段重叠的申请计算比较分。
- 贡献分 = 企业积分 / 比较组最高积分 × 100；全部零积分时贡献分均为零。
- 紧急分：普通40，温控风险紧急60，临床急需/急救100。临床急需与急救必须确认模拟证明。
- 风险分由演示表单输入30、80或100，不代表真实合规判断。
- 等待分 = 本申请等待分钟 / 比较组最长等待分钟 × 100。刚提交且无等待时为零。
- 总分 = 贡献分×40% + 紧急分×30% + 风险分×20% + 等待分×10%。总分最终保留两位小数，展示分项保留两位小数。
- 同分按风险分、提交时间、订单号排序；不使用语言模型生成分配结果。
- 先预留企业保底额度，再按分数分配共享余量。当前仅丙企业有150m³保底演示额度。同企业同一时段不能重复领取保底。
- 时段按自然日的半开区间计算。例如11月2日起3天，占用2、3、4日，5日不占用。资源余量逐日核验，取申请时段内最小余量。
- 已分配即锁定库容；取消或全部履约完成释放。首版不自动过期，部分发运期间保守地保留原锁定量。
- 同一批需求可以拆至多个匹配库区；当前未实现距离与碎片惩罚优化，不宣称求得全局最优解。
- 单笔提交即时处理；完整案例一次提交六条。已锁定的订单不会因后续申请而被强行重排。

## 旺季案例预期

案例固定申请日期为2026年11月2日，存储3天。冷藏申请总量750m³，共享冷藏资源500m³；冷冻申请100m³，对应资源150m³。

初次分配：甲200、乙150、丙150、丁0、己0、戊100。丙的150为保底预留。己因高风险进入应急待响应，甲的应急库仍未占用。

切换甲企业接受协作后，己获得应急库120m³。甲获得预计360演示积分，只有订单全部履约完成后才实际加分；不允许接受再取消刷分。模拟应急存储费为120×3×7=2520元，没有真实支付。

共享500m³满额后，不再额外提供不存在的50m³货架库容。改期仅提示重新查询，不承诺下一周一定可用。替代资源仍须温区匹配。

## 车辆模型

单车须同时满足温区、吨位、体积、到达耗时。匹配分由邻近、到达耗时、设备、可靠度各25%构成，距离和耗时仅为模拟预设值，不接地图实时路况。

150m³需求不能直接放入20m³或35m³车辆。首版允许分批，实际输入体积和重量，不自动把体积换算成重量。每批完成后扣减待运量，全部批次完成后才关闭存储订单；不得重复完成同一批刷积分。

## 与完整项目方案的差距

历史合规履约率修正、临近窗口紧急加分、完整资源可用时间窗、距离/碎片/溢价优化、自动催办、应急审核和第三方温控设备仍未实现。页面仅展示已实现的解释；后续若接真实业务，需要另行梳理药品储运、主体资质与数据要求。
